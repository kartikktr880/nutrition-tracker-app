# Internationalization (i18n) Implementation

## Overview
The Nutrition Tracker application now supports multiple languages through a comprehensive internationalization (i18n) system. This document outlines the implementation details, how to use the translation system, and how to add new languages.

## Key Features
- Support for multiple languages (English, Spanish, French, German, Chinese)
- Automatic language detection based on browser settings
- User language preference saved in localStorage
- Dynamic translation of UI elements
- Support for interpolating variables in translations

## Implementation Files

### JavaScript
- `scripts/i18n.js`: Core i18n manager for handling language switching and translations

### Translations
- `translations/en.json`: English translations (default)
- `translations/es.json`: Spanish translations
- `translations/fr.json`: French translations (to be added)
- `translations/de.json`: German translations (to be added)
- `translations/zh.json`: Chinese translations (to be added)

### Components
- `components/language-selector.html`: Language selector UI component for settings page

## How to Use Translations in HTML

### Basic Text Translation
To make a text element translatable, add the `data-i18n` attribute with the translation key:

```html
<h1 data-i18n="dashboard.welcome">Welcome</h1>
<p data-i18n="dashboard.today_summary">Today's Summary</p>
```

### Translations with Variables
For translations that contain variables, use the `data-i18n-params` attribute with a JSON object:

```html
<h1 data-i18n="dashboard.welcome" data-i18n-params='{"name":"John"}'>Welcome, John</h1>
```

In the translation file:
```json
{
  "dashboard": {
    "welcome": "Welcome, {{name}}"
  }
}
```

### Translating Placeholders
For input placeholders, use the `data-i18n-placeholder` attribute:

```html
<input type="text" data-i18n-placeholder="food_logger.search_food" placeholder="Search for food...">
```

## How to Use Translations in JavaScript

### Direct Translation
You can use the global `__()` function to translate strings in JavaScript:

```javascript
const message = __('common.success');
alert(message);
```

### Translation with Variables
You can pass variables for interpolation as the second parameter:

```javascript
const welcome = __('dashboard.welcome', { name: user.name });
document.getElementById('greeting').textContent = welcome;
```

### Listening for Language Changes
Your components can listen for language changes and update accordingly:

```javascript
document.addEventListener('languageChanged', (e) => {
    const { language } = e.detail;
    // Update your component based on the language change
    updateMyComponent();
});
```

## Adding a New Language

1. Create a new translation file in the `translations/` directory (e.g., `translations/fr.json`)
2. Copy the structure from `translations/en.json` and translate all values
3. Add the language to the supported languages list in `I18nManager.isLanguageSupported()`
4. Add the language option to the language selector component

## Translation File Structure

Translation files use a nested structure with namespaces to organize translations:

```json
{
  "common": {
    "save": "Save",
    "cancel": "Cancel"
  },
  "dashboard": {
    "welcome": "Welcome, {{name}}",
    "today_summary": "Today's Summary"
  }
}
```

## Best Practices

1. Use consistent keys across all translation files
2. Group related translations under common namespaces
3. Use descriptive key names that reflect the content
4. Keep translations concise and clear
5. Test translations in context to ensure proper formatting and layout
6. Consider text expansion/contraction in different languages when designing UI
7. Use variables for dynamic content rather than concatenating strings

## Translation Workflow

1. Extract new strings that need translation
2. Add them to the English translation file with appropriate keys
3. Share the English file with translators
4. Incorporate translated files back into the application

## Known Limitations

- Right-to-left (RTL) languages not fully supported yet
- Some third-party components may not be translatable
- PDF exports currently use the active language only
