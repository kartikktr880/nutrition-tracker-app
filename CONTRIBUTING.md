Thank you for your interest in contributing! This guide will help you get started with reporting issues, proposing features, and submitting code to the Nutrition Tracker project.

## How to Contribute

- Fork the repository
- Create a feature branch: `git checkout -b feature/your-feature`
- Make your changes (see [DEVELOPER_GUIDE.md](./DEVELOPER_GUIDE.md))
- Commit with clear messages: `git commit -m "feat: Add new feature"`
- Push to your fork: `git push origin feature/your-feature`
- Open a Pull Request (PR) to the main repository

---

## Reporting Issues

- Search existing issues before opening a new one
- Include clear steps to reproduce, expected vs. actual behavior, and screenshots/logs if possible
- Use descriptive titles and labels (e.g., `bug`, `enhancement`)

---

## Proposing Features

- Open an issue with the `enhancement` label
- Describe the feature, use case, and any relevant context
- Suggest possible implementation ideas if you have them

---

## Pull Request Process

- Ensure your branch is up to date with `main`
- Run all tests and type checks before submitting
- Follow the project's [coding standards](./DEVELOPER_GUIDE.md#coding-standards)
- Reference related issues in your PR description (e.g., `Closes #123`)
- Add screenshots or demos for UI changes
- Keep PRs focused and small when possible

---

## Code Review

- PRs are reviewed by maintainers and/or the community
- Address feedback promptly
- Be open to suggestions and improvements
- PRs may be merged after at least one approval and all checks pass

---

## Community Standards

- Be respectful and inclusive
- Use clear, constructive communication
- Help others and share knowledge
- Follow the [Code of Conduct](./CODE_OF_CONDUCT.md) (if present)

---

Thank you for helping make Nutrition Tracker better! If you have questions, open an issue or ask in Discussions.
